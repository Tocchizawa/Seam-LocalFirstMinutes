# Seam - 要件定義書

## 1. プロジェクト概要

**Seam**は、完全ローカルで動作する AI 議事録作成ツール。
Zoom等のオンライン会議中にバックグラウンドで PC 内部音声 + マイク音声を録音し、
リアルタイムで文字起こしを行い、プロジェクトのコンテキストを踏まえた議事録を自動生成する。

話者分離は v1 のスコープから外す。文字起こしは話者を区別しない平文（タイムスタンプ付き）として扱う。

### 1.1 コンセプト

- **完全ローカル**: クラウドAPI不要、プライバシー安全
- **非参加型録音**: 会議に参加者として入らず、PC内部音声とマイクをバックグラウンド録音
- **リアルタイム文字起こし**: 録音中にWhisperがストリーミングで文字起こし（会議中にテキストを確認可能）
- **コンテキストアウェア**: ローカルのプロジェクト資料をエージェントが自律調査（Claude Code的な動作）し、文脈を理解した議事録を生成
- **シンプル**: 話者分離は行わず、録音 → 文字起こし → 要約 の最短パス
- **複数プロジェクト対応**: 複数のプロジェクトを管理し、それぞれに独立したコンテキスト・議事録を保持

### 1.2 ターゲットユーザー

- 個人利用（1人のユーザーが複数プロジェクトの会議を記録）

### 1.3 ターゲット環境

- macOS (Apple Silicon: M1〜M4)
- メモリ: 16GB以上推奨
- GPU: Apple Metal 対応（Whisper/LLM高速化）

### 1.4 会議の想定規模

- 参加者: 人数制限なし（話者を区別しないため）
- 会議時間: 最長 **3時間**
- 形式: **Zoom等のオンライン会議**が主
- **ヘッドホン使用推奨**（スピーカー使用時はマイクが相手の声を拾い、内部音声と二重になるため）

### 1.5 配布方式

- **macOS インストーラー (.dmg)** で配布
- Ollama バイナリ + Python バックエンドバイナリを同梱
- AIモデル（Qwen3, Whisper）は**初回起動時にダウンロード**（セットアップウィザード）
- ユーザーが個別に brew install 等をする必要なし

## 3. 非機能要件

### 3.1 パフォーマンス

- リアルタイム文字起こし: **5秒以内の遅延**で表示
- 2トラックミキシング（動的レベル正規化含む）: **3分以内** (3時間音声、ffmpeg dynaudnorm + limiter)
- コンテキスト調査: **60秒以内**
- 議事録生成 (1時間会議): **3分以内**
- 全体パイプライン (3時間会議): 録音停止後 **15〜20分以内** に議事録完成

### 3.2 リソース管理

- **重いモデルは同時にメモリに載せない**（順次ロード→アンロード）
- Phase 1（録音中）: Whisper のみ (~3GB)
- Phase 2（録音停止後）: Whisper アンロード → LLM ロード → アンロード
- セッション作業データはパイプライン完了後に全削除

#### メモリ見積もり（16GB Mac）

```
Phase 1: 録音中
  macOS + Zoom:     ~5.0GB
  Tauri + React:    ~0.3GB
  Python Backend:   ~0.5GB
  Whisper medium:   ~3.0GB
  録音バッファ:       ~0.2GB
  ──────────────────────
  合計:             ~9.0GB (マージン: 7GB)

Phase 2: LLM使用時
  macOS:            ~4.0GB (Zoom終了後)
  Tauri + React:    ~0.3GB
  Python Backend:   ~0.5GB
  Qwen3 8B:         ~5.0GB
  ──────────────────────
  ピーク:           ~9.8GB (マージン: 6.2GB)
```

### 3.3 プライバシー・セキュリティ

- 全処理がローカルで完結（ネットワーク通信なし）
- 音声データ・議事録は外部に送信されない
- 初回セットアップ時のみモデルダウンロードでネットワーク使用
- Context Agent のファイルアクセスは repo_path + doc_dirs 内に制限（サンドボックス）
- Context Agent の Python 実行は subprocess + timeout で隔離（書き込み不可）

### 3.4 ユーザビリティ

- **GUIファースト**: 最低限のデスクトップアプリを v1 から提供
- **ワンストップインストーラー**: .dmg でインストール → 初回起動でモデルDL
- 操作は「プロジェクト選択 → デバイス選択 → 録音開始 → 自動で議事録完成」の最短フロー
- Ollama はパイプラインの LLM 使用直前に起動（録音中は不要なのでメモリ節約）
- **ヘッドホン使用推奨**の案内をUI上に表示

### 3.5 信頼性

- 録音中にアプリがクラッシュしても、RAW PCM データは保持
- パイプラインの各ステージで中間データを保存し、途中再開可能
- 完了済みデータは SQLite + output_dir の Markdown が正本

## 5. 操作フロー

### 5.1 メインフロー（録音→議事録）

```
1. アプリ起動
2. プロジェクトを選択
3. 「録音開始」押下
   → マイクデバイス選択（デフォルト: システム既定）
   → 内部音声ソース選択
4. 録音開始（並行動作）:
   → mic + system の2トラック同時録音（RAW PCM）
   → リアルタイムミックス → Whisper ストリーミング文字起こし
   → WebSocket 経由でGUIにリアルタイム表示
5. 会議終了、「停止」押下
6. 後処理パイプライン（順次実行・メモリ節約）:
   a. Whisper 残バッファ処理 → Whisper アンロード
   b. RAW PCM → WAV 変換
   c. 2トラック → 動的レベル正規化 → combined.flac 生成
   d. Ollama + LLM (Qwen3) 起動 → Context Agent がプロジェクト資料を自律調査
   e. コンテキスト + 全文書き起こし → Minutes Agent → 議事録生成
   f. SQLite 保存 + output_dir に Markdown 出力
   g. セッション作業ディレクトリ全削除
   h. LLM アンロード + Ollama 停止
7. 結果表示
   → 要約タブ: 議事録（Markdown）
   → 全文タブ: タイムスタンプ付き全文
```

## 6. 制約事項

- インターネット接続が必要なのは初回セットアップ時のみ（モデルDL）
- Whisper large-v3 は 16GB では重いため medium モデルをデフォルトとする
- 同時に複数の会議を録音する機能は対象外
- 前セッションのパイプライン実行中は新規録音を開始できない（メモリ競合回避）
- 既存音声ファイルの取り込みは対象外（録音のみ）
- macOS のシステム音声キャプチャには Core Audio Tap (macOS 14.2+) を優先し、未対応環境では ScreenCaptureKit (macOS 13+) または BlackHole を使う
- 全ての会議はプロジェクトに紐づく（プロジェクトなしの録音は不可）
- ヘッドホン使用推奨（スピーカーだと内部音声とマイクで二重に拾う）
- プロジェクト削除時に output_dir を残した場合、Markdown ファイルは読めるが GUI からの検索・表示はできない（DBが削除されるため）
- 話者分離は行わない（誰が話したかは文字起こしに反映されない）
- 3時間の会議 → 録音停止後の処理に最大15〜20分程度かかる可能性あり

## 7. 用語定義

| 用語 | 定義 |
|------|------|
| 内部音声 | PC のシステム音声出力（Zoom 等の相手の声） |
| マイク音声 | ユーザーのマイク入力（自分の声） |
| リアルタイムミックス | 録音中に mic + system を即座に混合して Whisper に供給する処理 |
| コンテキスト | プロジェクトの資料・コード・ドキュメントから抽出した背景情報 |
| 全文書き起こし | 要約前の、発言全てをタイムスタンプ付きで記録したテキスト |
| ドキュメントディレクトリ | プロジェクトに紐づくローカルの資料フォルダ。エージェントが徹底調査する対象 |
| パイプライン | 録音→文字起こし→コンテキスト調査→議事録生成の一連の処理フロー |
| セッション | 1回の会議に対応する作業単位。パイプライン完了後に作業データは削除 |
| 正本 | SQLite + output_dir の Markdown。セッション作業データは一時的なもの |
